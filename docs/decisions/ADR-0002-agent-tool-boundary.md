# ADR-0002：Agent 工具边界（v0.4）

## 状态

已采纳（2026-09-22）；2026-11-19 修订终端确认 UX 与 `ask_user`；2026-11-23 增加 Plan 模式边界。

## 背景

v0.4 需要「计划并改代码」能力。若默认自动执行任意 shell，风险过高。

## 决策

1. 默认工具仅限**当前工作区**：`list_dir` / `read_file` / `write_file` / `replace_in_file`
2. `run_terminal` **可选**（`su.agent.enableTerminal`），且**须用户确认后**才执行：
   - 确认 UI 在 **Chat / Agent Window 对话区**（允许一次 / 本会话总是允许 / 拒绝），避免系统模态框打断
   - 用户选择「本会话总是允许」后，**本会话内**后续终端命令不再询问
   - 新对话会清除会话级允许；写文件仍走 Keep/Reject
3. 写文件变更进入 Pending Diff，用户 **Keep / Reject**（可全部操作）
4. 不做无人值守的联网安装、提权、删除工作区外文件
5. **Ask 模式（v0.5）**可使用只读工具 `list_dir` / `read_file`，并自动注入工作区快照；**不可**写文件或跑终端
6. Agent 执行过程须在对话区展示**可见进度**（步骤摘要 + 可展开详情），不能只在结束时甩出最终答复
7. **`ask_user`**：真正分叉抉择或可选后续建议时，在对话区出反馈卡片（多选 + 补充说明）
   - `kind=choice`：用户关闭 → **继续当前方案，不做额外扩展**，不替用户在选项间做主
   - `kind=suggestion`：用户关闭 → **结束本轮**，不执行建议操作
   - 复杂/需求不清时可多次调用；仍禁止用它替代终端授权或例行改文件确认，避免无意义刷屏
8. **Plan 模式（v0.6.1）**：只读 `list_dir` / `read_file`，产出可编辑 Markdown 计划；**仅当用户点击 Build** 后才切 Agent 执行。Plan 内禁止写文件与终端。

## 后果

- 与 Cursor 全自动 Agent 仍有差距；安全性与可审阅性优先，同时减少重复弹窗摩擦
- Ask 可总结/浏览；Plan 先审计划再执行；改代码与 shell 仍走 Agent + 确认（可会话级放行终端）
- 后续版本可在 ADR 更新后放宽（例如按命令白名单持久化到 settings、计划落盘）
